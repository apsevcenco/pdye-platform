STAGE 2 — APPROVED SPECIFICATION ACCESS (NOT DEAL ROOM YET)

This is the important correction.

When a requester submits access request for a yacht, and the admin presses Approve, this does NOT open the deal room yet.

Instead, this first approval must grant access only to an extended anonymized specification view.

That extended spec view must include:

full technical specification

non-sensitive yacht information needed for serious interest

But it must still NOT include:

yacht name
yacht location
full photos
seller contact details
broker contact details
documents intended for deal room only

So after first admin approval, the requester gets access to a requested yacht detail page with anonymized extended info.

This yacht must also appear in the requester dashboard in a separate block such as:

Approved Requests

From there the requester can open that yacht’s anonymized detailed page.

DEAL ROOM SHOULD OPEN ONLY LATER

The deal room must NOT open automatically after first approval.

The correct logic is:

Listing exists
Interested broker/buyer requests access
Admin approves first-level access
Requester sees anonymized full specification
Admin separately communicates with listing owner/seller outside the platform if needed
If the opportunity becomes serious and ready for discussion, then admin manually opens a dedicated deal room
Seller and buyer are added to that deal room
NDA is sent automatically to both sides
Only after NDA is signed by both sides, access to deal room is granted
Then both sides can see each other, communicate, and access full deal information

This distinction is critical.

IMPORTANT CONCEPTUAL MODEL

A yacht request and a deal room are not the same thing.

Request flow:

used for access to anonymized specification

Deal room flow:

used only when admin decides to move the opportunity into active negotiation

So implement them as separate but linked entities.
