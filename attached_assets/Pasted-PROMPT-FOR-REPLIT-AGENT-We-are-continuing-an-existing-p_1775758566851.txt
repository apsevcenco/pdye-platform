AUTOMATION LOGIC

Implement the following logic.

A. When user clicks “Request Details”

If current behavior already creates access_request, keep that.

Then automatically:

create access_request
create deal with status:
pending_admin_review
add buyer to deal_participants
create activity log:
request_created
deal_created

If a deal for the same buyer + yacht is already open and not cancelled/closed, do not create duplicate deals. Reuse existing open deal if appropriate.

B. Admin review action

Admin dashboard must allow:

approve request
reject request
assign broker
optionally assign owner
enable NDA step
If approved:
deal status becomes nda_pending
broker participant is added
activity log created: request_approved
If rejected:
deal status becomes rejected
activity log created: request_rejected
deal room access remains disabled
C. NDA / Terms step

Before deal room opens, buyer must explicitly accept:

NDA
Terms of access / non-circumvention / confidentiality

Implementation requirement:

checkbox for NDA acceptance
checkbox for Terms acceptance
disabled Continue button until both are accepted
save timestamps to deals
create record in nda_acceptance_logs
create activity logs

After both accepted:

set deal status to nda_signed
set intro_locked = true
D. Intro lock

This is a core business step.

After admin approval + NDA acceptance:

intro must be formally recorded
broker assigned to deal
intro timestamp saved
create activity log intro_sent
set status to intro_sent
then enable deal room

The platform owner (admin/business) is the intermediary controlling the intro.

Do not expose unrestricted direct contacts before this step.

E. Enable deal room

After intro is locked:

deal_room_enabled = true
deal status becomes active

Only then user gets:

full deal room access
documents allowed by role
internal messages
deal status panel
