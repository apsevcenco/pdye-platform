PROMPT FOR REPLIT AGENT — DEAL ROOM UI / UX STRUCTURE

We are continuing the existing PDYE platform.

Your task now is to build the Deal Room interface structure in a clean, production-oriented way, based on the already defined business logic.

Do not redesign the whole platform.
Do not rebuild unrelated pages.
Focus only on creating a highly functional Deal Room page and related dashboard entry points.

The goal is not just to make a chat/file page.
The Deal Room must work as a real transaction workspace.

It must immediately answer these questions for the user:

What yacht/opportunity is this?
What stage is the deal currently in?
What is already unlocked?
What action is required next?
Where are the files, messages, and legal confirmations?
MAIN UX PRINCIPLE

The Deal Room must feel like a structured transaction cockpit, not a generic portal.

It should help move the deal forward.

That means:

strong hierarchy
clear statuses
obvious next actions
no clutter
no confusion between pre-activation and active room states
MAIN ROUTES

Use existing routing style if already present, but target something like:

/dashboard/deals
/dashboard/deals/:id

If the approved anonymized opportunity page already exists separately, keep it separate from the active deal room.

Important:

anonymized approved opportunity page is NOT the same as active deal room
active deal room opens only after both NDA signatures are completed
DEAL ROOM PAGE LAYOUT

Build the Deal Room page with this layout structure:

1. TOP HEADER / SUMMARY BAR

This must be the first visible block and remain very clean.

Show:

Deal Room title or Deal ID
yacht short identity
current room status
buyer-side status
seller-side status
created date
last activity date
admin quick actions if admin is viewing

Status examples:

NDA Pending
Partially Signed
Active
Closed
Cancelled

Display status badges clearly.

Also include a prominent primary action button depending on state:

Examples:

Sign NDA
Awaiting Counterparty Signature
Open Documents
Upload File
Send Message
Review Offer

This area must let the user understand the room state without scrolling.

2. STATUS TIMELINE / PROGRESS TRACKER

Directly under header, create a visual timeline showing the transaction stage.

Recommended stages:

Request Approved
Deal Room Created
NDA Sent
Buyer Signed NDA
Seller Signed NDA
Deal Room Activated
Documents Shared
Offer / Negotiation
Closed or Cancelled

Behavior:

completed stages visually marked
current stage highlighted
future stages muted
timeline should be readable on desktop and mobile

This is one of the most important UX blocks.

3. NEXT ACTION / ACTION CENTER

This should be a dedicated card near the top, highly visible.

Purpose:
show exactly what must happen next.

Examples:

Buyer must sign NDA
Seller has not signed NDA yet
Admin must assign seller participant
Documents are available for review
Offer can now be submitted
Awaiting admin review of uploaded file

Show:

current required action
who is responsible
optional deadline
CTA button if relevant

This card should reduce confusion and increase conversion/action rate.

MAIN CONTENT SECTIONS

The Deal Room page should then be split into logical sections.

Recommended desktop layout:

central main content area
right sidebar for compact status/info blocks

On smaller screens, stack sections vertically with tabs or accordions if needed.

8. COMMUNICATION HUB

Build a dedicated messaging area inside the deal room.

This should not be just a raw chat.

It should include:

A. Participant messages

Standard room messages between approved participants.

B. System messages

Automatic timeline messages such as:

NDA sent
NDA signed by buyer
NDA signed by seller
room activated
document uploaded
participant added
status changed
C. Internal admin notes

Only visible to admin, separate from participant-visible messages.

Requirements:

store timestamps
identify sender
differentiate system vs human messages visually
newest message input should be simple and reliable
only assigned participants/admin can access

Before room activation:

do not allow unrestricted direct communication between both sides
if needed, admin-only internal notes are acceptable

STATE-BASED UI BEHAVIOR

The room UI must change depending on stage.

A. BEFORE ACTIVATION (NDA pending / partially signed)

Allowed:

header
stage timeline
next action
legal/NDA status
limited room shell

Restricted:

no full communication between both sides
no full documents
no full gallery
no direct counterpart access beyond what rules allow

User should clearly understand:
“Deal room is being prepared. Full access unlocks after both NDA signatures.”

B. AFTER ACTIVATION

Unlock:

full gallery
documents
participant communication
legal records
offers section
full working room state

Make the transition visually clear.

C. CLOSED / CANCELLED

Room becomes read-only unless admin decides otherwise.

Show:

final status
final date
archived records
no further actions except admin archive/reopen if supported
